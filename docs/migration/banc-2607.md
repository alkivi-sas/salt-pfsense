# Banc pfSense Plus 26.07 : amd64 et armv7

Checklist du banc qui remplace le lab abandonné au lot 1. Le détail des commandes est dans [`lab.md`](lab.md) et dans les recettes [`docs/recipes/`](../recipes/README.md) ; ce fichier ne fait que les ordonner et dire quoi rapporter.

| Boîtier | Version | Architecture | Expériences visées |
|---|---|---|---|
| `lab-plus2607` | Plus 26.07 | amd64 | toutes |
| `lab-plus2607-armv7` | Plus 26.07 | armv7 | EXP-06 (support armv7), puis le reste si pfrest s'installe |

Code testé : `master` à partir du merge de la PR #19 (lots 0 à 8).

## 0. Préparation

- [ ] Remettre chaque boîtier en configuration d'usine et le rattacher au master Salt.
- [ ] Garder une copie de `/cf/conf/config.xml` d'usine (retour arrière entre deux séries).
- [ ] Brancher une VM cliente Linux sur le LAN de chaque boîtier (captures DHCP).
- [ ] Copier ou lier `tests/lab/scenarios/` vers `<file_roots>/lab/` sur le master.

## 1. Socle (recettes 01 à 04)

- [ ] Installer le minion Salt (recette 01).
- [ ] Distribuer les extensions : `salt <minion> saltutil.sync_all` (recette 02).
- [ ] Déployer les helpers dans `/opt/helpers` (recette 03, `examples/salt/helpers.sls`).
- [ ] Générer la clé API avec `openssl rand -hex 32`, la mettre chiffrée dans `pfsense:restapi:api_key` (recette 04).

## 2. Installation de pfrest (recette 05, EXP-06, EXP-07)

- [ ] `salt <minion> state.apply pfsense.restapi test=True`, puis sans `test`, puis une seconde fois : aucun changement attendu.
- [ ] `salt <minion> pfsense_restapi.status` renvoie la version de pfSense.
- [ ] Dans le WebGUI (System > REST API) :
  - seul `KeyAuth` est actif ;
  - l'utilisateur `salt-api` n'a ni `page-all` ni `api-v2-diagnostics-command-prompt-post`.
- [ ] `salt-call -l debug state.apply pfsense.restapi` sur le boîtier : la clé n'apparaît nulle part dans la sortie.

**armv7.** pfrest ne supporte pas officiellement armv7.
- [ ] Si `pkg-static add` refuse le paquet, noter le message exact et s'arrêter là pour ce boîtier : il reste sur FauxAPI. C'est un résultat d'EXP-06.
- [ ] S'il s'installe : `pfsense_restapi.status`, puis un module en lecture (`salt <minion> pfsense_alias.list_aliases`), avant de continuer avec les étapes suivantes.

## 3. Scénarios de référence (lab.md § 3, EXP-01, EXP-05)

Deux séries, depuis la configuration d'usine à chaque fois.

- [ ] Série FauxAPI : pillar `pfsense:api_backend: fauxapi`, `saltutil.refresh_pillar`, puis :

```bash
export LAB_MINION=<minion> LAB_SALT="ssh <master> sudo salt"
pipenv run pytest -m lab tests/lab -v
```

- [ ] Récupérer `/cf/conf/config.xml` → `fauxapi.xml`.
- [ ] Restaurer la configuration d'usine.
- [ ] Série pfrest : pillar `pfsense:api_backend: pfrest`, même commande.
- [ ] Récupérer `/cf/conf/config.xml` → `pfrest.xml`.
- [ ] `pipenv run python tests/oracle/diff_config.py fauxapi.xml pfrest.xml`.

## 4. Recettes par domaine (recettes 10 à 27)

Pour chaque fichier de `examples/salt/` : `test=True`, passage réel, second passage à zéro changement.

- [ ] Noter, pour au moins `filter_rule`, `nat_rule` et `alias`, le nombre de reloads pf (`/var/log/filter.log` ou `pfctl -si`) et la durée du run (EXP-03).
- [ ] Rejouer une recette avec `pfsense:pfrest:apply: deferred` et `examples/salt/apply.sls` (recette 07) : un seul reload par domaine attendu.

## 5. Concurrence (EXP-02)

- [ ] Lancer un run long (recette filter_rule) et modifier un alias dans le WebGUI pendant le run.
- [ ] Attendu : erreur `PfrestConflict`, run en échec propre, modification WebGUI conservée.

## 6. DHCP ISC → Kea (lab.md § 4, EXP-08)

Au minimum sur amd64.

- [ ] Préparer ISC avec les options 43, 132 et 66 (lab.md § 4).
- [ ] Capture ISC, migration `pfsense_dhcp_kea.migrated`, capture Kea, comparaison.
- [ ] **Question ouverte :** Kea démarre-t-il avec une `option-def` qui redéfinit l'option 66 ? Si non, noter l'erreur de Kea : le module devra émettre l'option 66 sans `option-def`.
- [ ] Second passage : aucun changement.
- [ ] Cas de refus : failover configuré, option absente de la table.

## 7. Après une mise à jour (recette 42)

- [ ] Désinstaller puis réinstaller le paquet pfrest (ou mettre à jour pfSense si possible), puis lancer un highstate : il doit passer sans intervention.

## À rapporter

Tout est anonymisé : pas d'adresse publique, pas de MAC réelle, pas de nom de site.

- Sorties `--out=json` de chaque étape en échec, et le résumé pytest des deux séries.
- `fauxapi.xml`, `pfrest.xml` et la sortie de l'oracle.
- Captures DHCP et `diff` des options.
- Mesures de reloads et de durées.
- Le message exact de `pkg-static add` sur armv7.

Ces éléments alimentent les fiches `docs/rd/05-experiences/` (EXP-01 à EXP-08), le registre `tests/oracle/accepted_diffs.yaml` et le journal `docs/rd/journal.md`.
